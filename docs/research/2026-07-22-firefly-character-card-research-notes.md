# 流萤角色卡 & 四张 HSR 原型 —— 只读调研笔记

> 本笔记为只读调研,未对代码或数据做任何修改。供实施该 todo 时参考。

## 1. 仓库现状盘点(已核实的事实)

**已有的流萤角色卡资产**:`.tmp/firefly-character-tavern.png`,736×736,PNG 内已正确嵌入 `tEXt` 的 `chara`(CCv2)和 `ccv3`(CCv3)两个 base64 字段,`spec_version` 均为完整规范。内容来自第三方创作者 `bananashark892`,标签包含 `Flirty/Obsessive/Possessive/Romantic/Mature` 等擦边风格 tag,和官方人设的基调不完全一致 —— **这是一个需要确认的取舍点**:是直接用这张现成卡(需确认来源许可与内容是否符合产品调性),还是基于官方人设重新撰写一版 PomChat 自己的流萤角色卡。

**后端角色卡管道**(`apps/api/src/modules/character-cards/adapter.ts` + `character-card-routes.ts`)已经比较完整:
- PNG `tEXt` 解析优先取 `ccv3`,回退 `chara`;JSON 直接解析;10MB 上限;深度/字符串长度校验防止恶意卡片。
- 导入 PNG 格式的卡片时,原始 PNG 字节会存进 `assetStore`(`raw_object_key`),`/v1/characters/:id/avatar` 按原图返回 —— **"原始 PNG 资产保存"这条后端其实已经做了**,已有一条测试(`character-routes.test.ts`)验证 avatar 接口返回合法 PNG。
- 导出时如果目标格式与来源格式相同且有 `raw_object_key`,会返回原始文件而不是重新生成的占位图;跨格式导出(如 PNG→JSON)天然丢图属预期行为。

**真正确认存在的缺口**:
1. **前端从未展示头像图片**。`CharacterImport.tsx` 预览区、`App.tsx` 的联系人列表 / 聊天头部 / 消息气泡 / 档案页 hero,全部用 `character.name.slice(0,1)` 的文字占位头像,没有任何地方 `<img src=".../avatar">`。`NormalizedCharacterCard` 类型里也根本没有 avatar/image 字段。这是"头像展示"缺口的准确定位。
2. **没有用流萤这张真实卡片跑过的导入测试**。现有唯一的角色卡路由测试用的是合成的"星遥"卡(由 `exportCharacterCard` 生成的 1×1 空白占位图),没有覆盖过真实带插画的 PNG、真实大小的 base64 payload、`creator_notes`/`tags`/`alternate_greetings` 等扩展字段。
3. **产品页面结构与四张原型不是逐页对应关系**。当前 `App.tsx` 是一个页面内 `chat/profile/memories` 三态切换 + 全局设置弹窗,而不是原型里"聊天、档案、记忆、设置"四个各自独立、信息密度和交互控件都不同的页面(见第 4 节逐页对比)。这违反 AGENTS.md 里"原型页面 → 路由/组件 → 验收状态"逐页映射的门禁要求。

## 2. SillyTavern(Tavern)角色卡规范要点

- **两代规范**:V2(`spec: "chara_card_v2"`)和 V3(`spec: "chara_card_v3"`,向后兼容 V2 字段)。核心字段:`name`、`description`、`personality`、`scenario`、`first_mes`、`mes_example`、`creator_notes`、`system_prompt`、`post_history_instructions`、`alternate_greetings`、`tags`、`creator`、`character_version`。
- **PNG 嵌入方式**:标准做法是把 base64 编码的 JSON 写进 PNG 的 `tEXt`(或 `zTXt` 压缩版)chunk,V2 用关键字 `chara`,V3 用关键字 `ccv3`,两者可以同时存在(向后兼容)。仓库现有的 `.tmp` 卡片和 adapter.ts 的实现都符合这个约定。
- **V3 新增但仓库目前未处理的字段**:
  - `assets`:数组形式的多图资源(表情差分 `emotion`、图标 `icon`、背景 `background`、用户头像 `user_icon`),其中 `type=icon` 且 `name=main` 的资源规范上应作为角色主图标。目前 adapter 只从 PNG 容器本身取"原图"当头像,不解析 `assets` 数组 —— 如果以后要支持表情差分或卡内独立头像资源,需要补这块解析逻辑。
  - `character_book`:角色专属 lorebook(世界书),含 `scan_depth`、`token_budget`、`recursive_scanning` 等触发/预算控制字段。当前仓库的 `NormalizedCharacterCard` 没有消费这个字段(不影响头像/导入这两个 todo,但和"补齐角色卡"整体目标相关,可能是后续范围)。
  - `extensions`:允许任意未知键,规范要求应用不得删除未知扩展字段。adapter.ts 目前用 `preserved_data`(`structuredClone(source)`)整份保留原始 JSON,导出时用回 `preserved_data`,这个原则已经遵守。

## 3. 流萤(Firefly)官方人设参考要点

来源:百度百科、知乎、虎扑社区等公开资料综合(未能直接抓取 Fandom 页面正文,以下为搜索结果摘要,建议正式撰写文案前再核对官方文本原文避免转述失真)。

- **身份**:游戏《崩坏:星穹铁道》角色,虚构组织"星核猎手"成员,化名"萨姆"(SAM),常以机甲形态战斗。
- **身世**:来自已覆灭的跨星球国家"格拉默共和国",是该国量产的基因改造战士,本应在与"虫群"的战争中早夭;患有"失熵症"这一慢性绝症,生命短暂。
- **动机**:为寻找"活下去"的可能性而加入星核猎手,本质是在对抗被设定好的命运/"保质期"。
- **性格**:外表带着忧郁诗意(会在脆弱的美好事物——流萤、蝴蝶等——中寻找诗意),内核坚韧、拒绝向命运低头;对触碰/亲密关系较为怯生(touch-starved 式的细腻),同时在关键时刻表现出钢铁般的意志。
- **外观设计语言**:刻意避开机战动画常见的紧身战斗服路线,采用学院风连衣裙,整体白色基调,发箍/领巾突出清纯感;仓库现有卡片里提到的"撕裂旗帜蝴蝶结""渐变袜(青→棕,象征生命力从旺盛到枯竭)""绿色羽毛(战友的牺牲)"等象征设计,与官方美术设定的方向一致,可作为文案素材,但因来源是第三方创作者的解读,正式使用前建议再对照官方美术设定集/角色官网文本复核一次,避免把同人演绎当官方设定写死。

## 4. 四张 HSR 短信原型逐页核对清单

四张原型截图位置:`docs/v0.1.0/product/页面/{角色聊天页,角色档案页,角色记忆页,角色设置页}/*.png`。以下是逐页要点,供实施时按 AGENTS.md 门禁逐项截图比对。

**① 角色聊天页(短信列表 + 会话)**
- 左侧联系人列表:圆形真实插画头像(非文字占位)、名字、末条消息摘要、当前选中态有白色描边高亮卡片。
- 列表底部固定"筛选"入口 + `UID:xxx` 标识。
- 右侧会话区顶部是角色名 + 一句签名/状态短句(不是"最近上线"这类系统文案,是角色语气的句子)。
- 消息气泡:对方灰底方角偏圆角、带头像贴在气泡外侧左上;我方使用暖色(浅橙/米色)气泡贴自己头像在右侧;每条对方消息上方有一次角色名标签。
- 底部是"快速回复选项"两条横条(图标+文案),不是仓库当前实现的自由输入框;自由输入框是否也存在需要向下滚动截图确认,不能假设当前 App.tsx 的输入框样式是对的。

**② 角色档案页**
- 顶部深色 banner + 半透明大徽章图形背景,不是纯白卡片。
- 左侧联系人列表在这一页依然保留(同一整体布局的右侧内容切换,不是跳转到独立无侧栏页面)。
- 头像为大尺寸方角圆边插画,右侧角色名 + 定位徽标图标 + 身份副标题(如"星际和平公司「天才俱乐部」成员")。
- 引用式一句台词卡片(带引号排版)。
- 分区标题用小型菱形/棱形项目符号("◆简介""◆核心性格"...),"核心性格"下是多个胶囊标签 + 段落说明;有"关系摘要""共同经历摘要"(含项目符号列表)等仓库当前完全没有的信息模块。
- 右侧两张功能卡片:"记忆"入口、"角色设置"入口,带图标和跳转说明副文案——当前实现是顶部 tab 按钮,不是右侧卡片式入口。

**③ 角色记忆页**
- 二级左侧导航("银天记录/好友列表/共同回忆/黑名单"),当前实现的"记忆"只有单一列表,缺少这层子导航。
- 主区是"共同回忆"卡片流:每条含缩略图(场景/角色插画)、标题、正文摘要、日期时间戳、单条删除图标;顶部有 `x/50` 条数上限提示和整体删除图标。
- 底部有引导语句(斜体/居中的一句总结文案)。

**④ 角色设置页**
- 顶部有返回箭头 + "角色设置"标题,右上是"好感度等级 N"带跳转箭头——当前实现完全没有好感度这个概念。
- 头像可编辑(铅笔图标)。
- 分组"角色数据"(导入角色卡/导出角色卡/重置角色数据)与"模型配置"(模型选择/回复风格/记忆强度)两个独立分组,每项都是图标+主标题+副说明+右侧当前值或箭头的列表行样式,不是仓库当前的单一 modal。
- 底部有一条 info 图标+浅色说明条("上述设置为低频配置,不影响日常对话体验")。

**跨页共性**:统一的左侧联系人列表宽度、头像圆角规则、顶部"短信"品牌角标(消息气泡图标+"短信"文字)在四页里位置/尺寸是否一致,需要用同一浏览器视口截四张图后叠加比对,而不是分别目测。

## 5. 建议的下一步顺序(仅供参考,不代表已执行)

1. 先决定流萤卡片内容来源(现成 `.tmp` 第三方卡 vs 基于官方人设重写)——这是需要确认的产品/合规决策,不是纯技术问题。
2. 给 `NormalizedCharacterCard` / 预览接口补上 avatar 相关字段和 `<img>` 渲染,覆盖列表、聊天头部、消息气泡、档案 hero、导入预览五处占位头像。
3. 用真实的 `firefly-character-tavern.png` 补一条端到端导入测试(preview → import → avatar → export 四步,校验图片字节和关键文本字段都不丢)。
4. 按第 4 节清单逐页重做/校对聊天、档案、记忆、设置四个页面结构,而不是维持当前的单页三态切换。
